# Browser Guard MCP

**Дайте агенту браузер, но не свой браузер.**

Browser Guard даёт AI-агенту отдельный браузер, а не ваш. Он запускает пустой Chrome, разрешает только публичные HTTP(S)-страницы и спрашивает подтверждение, прежде чем ввести пароль, номер карты или одноразовый код.

Он также блокирует localhost и частные адреса, не даёт загрузить известные секретные файлы и держит снимки страниц в памяти, а не на диске. В локальном журнале нет URL и текста страниц.

Это MCP-сервер для Codex, Claude, OpenCode и других MCP-клиентов. Каждое действие проверяется в одном месте.

Версия 0.1.0. Сначала macOS: диалог чувствительного ввода использует `osascript`.

English version: [README.md](README.md).

## Зачем

Агенту всё чаще нужно нажимать кнопки, заполнять формы и читать реальные страницы. Если отдать ему рабочий браузер, он получит ещё и сессии, сохранённые пароли, расширения и локальную сеть. Guard оставляет полезную часть, а остальное не отдаёт.

## Быстрый старт

Требования:

- Node.js 20 или новее.
- Google Chrome.
- [`@playwright/mcp`](https://github.com/microsoft/playwright-mcp) 0.0.76 или новее.

```sh
git clone https://github.com/alexandryasukaitisss-cmd/browser-guard-mcp.git
cd browser-guard-mcp
npm test
```

Установите Playwright MCP и запомните абсолютный путь к его CLI:

```sh
npm install -g @playwright/mcp
npm root -g
# <npm-root>/@playwright/mcp/cli.js
```

Создайте конфигурацию:

```sh
mkdir -p ~/.config/browser-guard-mcp
cp examples/config.example.json ~/.config/browser-guard-mcp/config.json
```

Измените значения:

- `runtimeDir` — приватный каталог состояния. Guard создаёт его с правами `0700`.
- `chrome.nodeCommand` — Node, запускающий Playwright MCP. Если не указан, берётся текущий процесс Node.
- `chrome.playwrightCli` — абсолютный путь из `npm root -g`.
- `capabilities` — профили, описанные ниже.

Проверьте, что конфигурация читается:

```sh
node src/cli.cjs --check --config ~/.config/browser-guard-mcp/config.json
```

Добавьте сервер в MCP-клиент. Пример — [`examples/mcp-client.json`](examples/mcp-client.json):

```json
{
  "mcpServers": {
    "browser-guard": {
      "command": "/usr/local/bin/node",
      "args": [
        "/Users/you/src/browser-guard-mcp/src/cli.cjs",
        "--config",
        "/Users/you/.config/browser-guard-mcp/config.json"
      ]
    }
  }
}
```

Перезапустите клиент и попросите:

> Открой `https://example.com` и перескажи страницу. Используй `browser_route_open` с `intent: "read"`.

Для интерактивной работы сначала включите профиль:

> Вызови `browser_capability_activate` с `profile_id: "public-interact"`, открой `https://github.com` и нажми на поле поиска.

## Инструменты

Сервер отдаёт девять инструментов Guard. Сырые `browser_*` инструменты наружу не выходят.

| Инструмент | Назначение |
| --- | --- |
| `browser_route_open` | Открыть публичный HTTP(S)-адрес. `intent`: `read`, `extract`, `visual` или `interactive`. |
| `browser_route_call` | Вызвать разрешённую операцию на активной странице. |
| `browser_capability_activate` | Включить профиль на ограниченное время. |
| `browser_capability_status` | Показать активный профиль и срок. Без данных страницы. |
| `browser_action_prepare` | Создать одноразовый ID действия; диалог показывается только для чувствительного ввода. |
| `browser_evidence_bundle` | Снять ограниченный снимок страницы и консоль в память. |
| `browser_evidence_get` | Прочитать действующий снимок из памяти. |
| `browser_guard_status` | Показать состояние браузера и профиля. Без данных страницы. |
| `browser_compatibility_summary` | Показать обезличенную сводку локального журнала. |

`browser_route_call` принимает только эти операции:

| Операция | Разрешение профиля |
| --- | --- |
| `browser_navigate`, `browser_navigate_back` | `navigate` |
| `browser_snapshot` | `read` |
| `browser_console_messages`, `browser_wait_for`, `browser_close` | `observe` |
| `browser_click`, `browser_hover`, `browser_type`, `browser_press_key`, `browser_select_option`, `browser_fill_form`, `browser_file_upload` | `interact` |

Всё остальное запрещено. В том числе выполнение JavaScript и произвольного кода, cookies, storage, вкладки, просмотр сетевых запросов и скриншоты.

## Профили возможностей

Профиль задаёт шаблоны DNS-хостов, разрешённые операции и максимальное время жизни. По умолчанию включён `public-read`: навигация и чтение без интерактивных действий.

```json
{
  "defaultProfile": "public-read",
  "profiles": [
    {
      "id": "public-interact",
      "hosts": ["github.com", "*.github.com"],
      "operations": ["navigate", "read", "extract", "observe", "interact"],
      "maxTtlSeconds": 900
    }
  ]
}
```

Шаблоны хостов: `*`, точный хост или `*.поддомен`. IP-адреса как шаблоны запрещены. Разрешение живёт в памяти и истекает; перезапуск Guard его сбрасывает.

## Чувствительный ввод

Перед вводом в поле номера карты, пароля или одноразового кода агент обязан:

1. Вызвать `browser_action_prepare` с точным инструментом и аргументами.
2. Guard покажет нативный диалог macOS, где по умолчанию выбрано **Deny**. При согласии вернётся одноразовый ID.
3. Передать ID в `browser_route_call` с теми же инструментом и аргументами.

ID привязан к разрешению, точному origin, имени инструмента и SHA-256 аргументов. По умолчанию он живёт 60 секунд. Повтор, изменение аргументов или смена origin отклоняются. В системах без macOS диалог показать нельзя, поэтому чувствительный ввод запрещён.

Определение опирается на явные признаки поля: `type=password`, токены `autocomplete` для карт и одноразовых кодов, подписи вроде «Card number», «CVV», «Password», «One-time code», «Номер карты», «Пароль».

**Поле может не распознаться.** Нестандартный виджет, подпись только «Verification code» или неполное описание от агента могут не вызвать диалог. Считайте подтверждение защитой от случайного ввода, а не средством предотвращения утечек. Не давайте агенту настоящие данные карты. Полная граница описана ниже.

## Доказательства и локальный аудит

- `browser_evidence_bundle` хранит ограниченный снимок и консоль в памяти процесса. Они истекают вместе с разрешением и не становятся файлом, которым управляет Guard.
- Журнал совместимости — локальный JSONL с правами `0600`. Он хранит только время, операцию, бэкенд, намерение, успех или ошибку, категорию ошибки, класс операции, длительность, класс клиента и число загруженных файлов. В нём нет URL, доменов, текста страниц, аргументов, скриншотов, cookies и ID подтверждений.
- Playwright может писать временные снимки в приватный выходной каталог. Guard удаляет его при закрытии. Журнал ведётся отдельно и не содержит содержимого.

## Демонстрация

```sh
PLAYWRIGHT_MCP_CLI="$(npm root -g)/@playwright/mcp/cli.js" node demo/blocked.cjs
```

Ожидаемая форма вывода:

```text
public page: https://example.com/ via chrome
loopback: NETWORK_DENIED
local server requests: 0
```

Локальный сервер настоящий. Последняя строка — главное: запрос до него не дошёл.

## Граница безопасности

Что Guard действительно делает:

- Разрешает только HTTP(S), стандартные порты 80/443, без учётных данных в URL.
- Отклоняет литеральные частные, loopback, link-local, multicast и специальные адреса до навигации.
- Пропускает весь трафик Chromium через loopback egress-прокси. Прокси разрешает каждое имя, отклоняет непубличные результаты, повторно применяет шаблоны активного профиля и покрывает редиректы и подресурсы.
- Запускает Chrome с `--isolated`, приватным профилем, без storage state и service workers, с минимальным окружением без внешних proxy-переменных и учётных данных.
- Пропускает к браузеру только перечисленные операции.
- Запрещает загрузку известных секретных файлов: `.env*` (кроме примеров), приватные ключи, данные Keychain, `auth.json`, `.ssh`, `.aws`, `.kube` и похожие места, после `realpath`.
- Требует одноразового нативного подтверждения для карты, пароля и одноразового кода.

Чего Guard не делает:

- Он не является песочницей операционной системы. Chromium работает с правами пользователя. Эксплойт браузерного движка выходит за рамки этой модели.
- Публичные страницы могут быть вредоносными, вводящими в заблуждение или враждебными. Guard управляет доступностью, а не содержанием.
- Egress-прокси — граница для HTTP(S)-трафика, а не доказательство защиты от всех побочных каналов (например, WebRTC, QUIC или ошибок браузера).
- Определение чувствительных полей эвристическое. Поле с необычной подписью можно пропустить. Диалог — не гарантия, что секрет никогда не будет введён.
- Проверка загрузок смотрит пути и имена, а не содержимое файлов.
- В изолированном профиле нет ваших сессий. Сайты, которым нужен существующий вход, работать не будут; это сделано намеренно.
- Playwright и Chromium сохраняют собственное поведение и вывод. Проект их не аудирует и не патчит.

Полная граница и остаточные риски — в [docs/threat-model.md](docs/threat-model.md). Архитектура — в [docs/design.md](docs/design.md).

О проблемах безопасности сообщайте приватно, как описано в [SECURITY.md](SECURITY.md).

## Разработка

```sh
npm test          # 49 детерминированных тестов, без браузера
npm run check     # проверить пример конфигурации
npm run smoke -- --config /path/to/config.json
```

Живой smoke требует Chrome, Playwright MCP и доступ в интернет. Он открывает публичную страницу, снимает доказательства в память и проверяет, что loopback-маршрут отклонён.
